ZHA to Z2M Migration Tool

Migrate a Home Assistant ZHA Zigbee network to Zigbee2MQTT without re-pairing your devices.

Where to find these files

For Step 1 (zigbee.db and the device/area registries): create and export a full Home Assistant backup and extract it. The File editor seems to not expose the .storage/ directory, where the registry files live, so a backup is the easiest route here. Extract the outer .tar file, then extract the homeassistant.tar.gz inside it (gunzip, then untar), which gives you a homeassistant/ folder - the files below all live under homeassistant/data/.

  • homeassistant/data/zigbee.db - ZHA's own database (network settings + device list). Needed for Step 1.
  • homeassistant/data/.storage/core.device_registry - your devices' names. Needed for Step 1.
  • homeassistant/data/.storage/core.area_registry - your rooms' names. Optional, Step 1.
  • homeassistant/data/zigbee2mqtt/configuration.yaml - the Zigbee2MQTT add-on's own config, if it's already installed. Optional, Step 1.
  • homeassistant/data/zigbee2mqtt/database.db - only appears after Zigbee2MQTT's first successful start (see Step 2). Needed for Step 3.

If extracting the backup gives you trouble:

  • Extracting homeassistant.tar.gz and getting "unsupported format" means the backup was created with encryption enabled - create or download an unencrypted one instead (leave encryption unchecked when creating it in Settings → System → Backups).
  • .storage/ is a hidden (dot-prefixed) folder, so your file manager may hide it by default. On macOS: press Cmd+Shift+. in Finder to show hidden files, or run ls -a in Terminal. If it's still inaccessible, rename it (mv .storage storage_tmp) so it's no longer hidden.

For Steps 2-4 (uploading configuration.yaml, and downloading/re-uploading database.db): install the official File editor add-on from the Home Assistant add-on store. It provides the easiest way for getting our modified files back into Home Assistant.

1

Generate configuration.yaml from your ZHA backup

Upload the ZHA files below. This reads your existing Zigbee network's settings (so devices don't need to be re-paired) and your device/room names, and turns them into a Zigbee2MQTT config.

This is zigbee.db, found at homeassistant/data/zigbee.db in your Home Assistant backup.
This is core.device_registry, found at homeassistant/data/.storage/core.device_registry. It's a JSON file with no file extension.
This is core.area_registry, found at homeassistant/data/.storage/core.area_registry. Home Assistant only requires device names to be unique per room, but Zigbee2MQTT requires them to be unique overall - providing this file appends the room name (e.g. "Lamp 2 (Kitchen)") to any device name that would otherwise collide with one in a different room.
If the Zigbee2MQTT add-on is already installed, upload its current configuration.yaml (at homeassistant/data/zigbee2mqtt/configuration.yaml) here. Your network settings and device list will be merged into it, so you get one complete, ready-to-use file (mqtt/serial/frontend settings preserved) instead of a fragment you'd have to merge by hand.

Start Zigbee2MQTT once to form the network

      

      
This step happens in Home Assistant / the add-on itself - there's nothing to upload here. The File editor add-on (mentioned above) is the easiest way to do the delete/upload/download actions below.

      

        Before you start: make sure the MQTT integration is set up in Home Assistant.
        Without it, Zigbee2MQTT can fail to start with errors like Got unexpected response from the
        API: Service not enabled / Failed to get services from Supervisor API.

Info If the network doesn't form or database.db never appears

        

          According to user reports, this doesn't always succeed on the first start/stop attempt - you may
          see errors like RESET_WATCHDOG or Failed to start EZSP layer with
          status=HOST_FATAL_ERROR in the log, with no database.db appearing afterward.
          If that happens, try toggling the ZHA integration in between attempts: stop Zigbee2MQTT, briefly
          enable ZHA, start then stop Zigbee2MQTT again, disable ZHA, then
          start/stop Zigbee2MQTT once more. This has been reported to eventually produce a working
          database.db.
        

        

          Afterward, double-check that file: it should contain exactly one line, for the coordinator
          ("id":1,"type":"Coordinator",...). If it has more lines than that - e.g. because ZHA
          joined devices while briefly re-enabled - open it in a text editor and delete every line except
          that first coordinator one before moving on to Step 3.

Add your devices to database.db

      

      
This adds every device from your ZHA backup into Zigbee2MQTT's device database, so it recognizes them by their existing network address instead of you having to re-pair each one. It reuses the zigbee.db file you selected in Step 1, so make sure that's still filled in above.

4

        
Finish the migration

      

      

        Upload the updated database.db from Step 3 back into homeassistant/data/zigbee2mqtt/
        (e.g. via File editor), overwriting the one from Step 2, then start Zigbee2MQTT again. Your devices will appear as "unsupported" -
        interview each one from the Zigbee2MQTT frontend to complete the migration. Interview mains-powered
        routers first, then other mains-powered devices, then battery-powered devices last - you'll need to wake
        each battery-powered device manually during its interview.
      

      

        Tip: you can find the Device interview button by clicking the
        device's name to go to its detailed info page. In the bottom-right corner there's a row of icons -
        click the ℹ️ one to start the interview. Alternatively, you can also switch to the Devices
        tab via Zigbee2MQTT's main navigation. The table view exposes the same row of icons for every listed
        device, so the interview process can be started in rapid succession for many devices.
